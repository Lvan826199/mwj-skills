# 交接记忆模板

文件名：`handoff-<YYYY-MM-DD>.md`，类型 project。参考范例：AiTestProject 记忆 `handoff-2026-10-08.md`、`handoff-2026-10-12.md`。

```markdown
---
name: handoff-<YYYY-MM-DD>
description: <一行：做到哪了 + 下一步起点，例如「M32 接入 P0–P6 已交付，真机三条全过；下一步先跑 xx 验收脚本」>
metadata:
  type: project
---

## 结论
<一句话：这一段工作的结果>

## 做了什么
- <事项>：提交 <hash>，产物 <路径>，验证 <测试 / 回执编号 + 日期>

## 实测状态（写交接时现查）
- 仓库：<branch>@<hash>，未提交 <有 / 无>，未推送 <n> 个
- 服务 / 进程：<端口 → 进程 → 谁起的>；<不能碰的端口与归属>
- 后台任务 / 定时任务：<在跑 / 已停>

## 用户的决定与硬约束（原话）
- 「……」（YYYY-MM-DD）

## 未决项
- [ ] <等用户拍板 / 等回执 / 等外部>

## 残留
- <没清掉的测试数据、临时文件，以及怎么清>

## 下一步起点
1. <先读哪个文件 / 先跑哪条命令>
2. ……

## 方法教训
- <这一段里学到的、下次能直接用的做法>

**Why:** <为什么要记这份交接：例如上下文要压缩、换机器、额度耗尽>
**How to apply:** 恢复时先读这份，再按「下一步起点」做；硬约束不推翻。
```

## 记忆进仓库的三种方案（项目还没定时供参考）

| 方案 | 做法 | 优点 | 缺点 | 例子 |
|---|---|---|---|---|
| 同步脚本 | 本机桶和 `docs/memory/` 双向同步，只增不删，带 `--check` | 不依赖 harness；Codex 也能写 | 要记得跑；删除要两边手动删；选错桶出过事故 | MoneyFree `scripts/sync_memory.py` |
| 软链 | 本机 `memory/` 软链到 `docs/agent-memory/` | 不用同步 | 每台机器要重新建链；敏感内容要另外分流 | Sujian |
| 仓库 MEMORY.md 为权威 | CLAUDE.md 里用 `@MEMORY.md` 导入；本机只放机器相关的内容 | 最简单 | 要手动区分写在哪边；不能放密钥 | OcrYoloEngine |
