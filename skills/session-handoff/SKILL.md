# Session Handoff：收工、迁移、恢复

先判断是哪种模式：

| 用户说 | 模式 |
|---|---|
| 「收工」「交接」「今天先到这」、上下文快满 | **A 收工交接** |
| 「挪到 X 目录」「把那个目录的记忆和对话继承过来」 | **B 迁移** |
| 「恢复任务继续执行」「额度恢复了」「重启后继续」、/compact 之后 | **C 恢复** |

## A. 收工交接

1. **盘点**（只读）：
   ```bash
   git status --short; git log --oneline @{u}.. 2>/dev/null   # 未提交、未推送
   ```
   还要查：在跑的进程和端口（只看自己起的）、后台任务和子代理、定时任务、残留的测试数据或临时文件。
2. **收拾**：
   - 自己起的临时服务按 pid 停掉，别人的不碰。
   - 测试数据按约定清理；清不掉的列进交接文档。
3. **更新进度文件**：`task_plan.md`、`progress.md`（或 `.planning/<当前任务>/` 下的同名文件），把状态改对，勾掉已完成项。
4. **写交接**：按 `references/handoff-template.md` 写一条 project 类记忆 `handoff-<YYYY-MM-DD>.md`，并更新 MEMORY.md 索引。必须写清三件事：
   - **下一步从哪开始**：先跑哪个命令、先读哪份文件。
   - **用户的硬约束和已拍板的决定**：原话照抄，例如「没说做就不允许改代码」「不要重开方案讨论」。
   - **未决项**：等用户决定的、等真机回执的。
5. **记忆在仓库里的**（`docs/memory/`、`docs/agent-memory/`、根目录 `MEMORY.md`）：同步、提交、推送。有同步脚本的按项目方式做，例如 MoneyFree 的 `scripts/sync_memory.py`。
6. 汇报：一段话说清做完了什么、没做完什么、下次从哪开始，最后给出交接文件路径。

> 问题解决后的那一轮还要调用 `postmortem`。交接只记状态，归因单独写。

## B. 迁移（工作目录、会话、记忆）

Claude Code 按**启动目录**分桶：`~/.claude/projects/<把路径里非字母数字的字符都换成 - >/`。每个桶里有 `<会话id>.jsonl` 和同名的附属目录，以及 `memory/`。

1. **确认目标**：用户要在哪个目录下工作。目标桶不存在时，先请用户在目标目录启动一次 `claude`。
2. **列清单**（只读）：源桶有哪些会话（看 jsonl 首行的时间和 `custom-title.json` 辨认）、哪些记忆。
3. **逐条分拣记忆归属**：
   - 本项目的：搬过去。
   - 机器级的通用偏好（模型、权限、定时任务）：留在原处。
   - 别的项目的：不动。
   - 归属拿不准的：问用户。
4. **复制会话**：用 `scripts/copy_sessions.py`，先加 `--dry-run` 看一遍，再正式执行。脚本只复制、逐文件比对 sha256；目标里已有同名但内容不同的文件时报错，不覆盖。**正在进行的会话**（包括当前这个）还在不断写入，等它结束后再复制。
5. **复制记忆**：只复制分拣为本项目的记忆文件。重名的先 `diff`，有冲突交用户定。复制后更新目标桶的 MEMORY.md 索引。
6. **写指针记忆**：在目标桶写一条 reference 类记忆 `related-memory-locations.md`，记下搬了什么、故意留下什么、留在哪里。
7. **删原件**：只有用户明确说「删掉」才删，删之前再核对一次。两个会话同时整理过同一批记忆的目录，不要擅自删，留哪边由用户决定。

## C. 恢复（中断后续接）

按顺序读，读完**先汇报盘点结果，再续做**：

1. MEMORY.md 索引、最新的 `handoff-*.md`
2. 当前任务的 `task_plan.md`、`progress.md`、`findings.md`（根目录或 `.planning/<任务>/`）
3. `git status`、`git log --oneline -10`、`git fetch` 之后和远端的差异：有没有另一个窗口或另一台机器推了新东西
4. 后台任务和子代理、在跑的服务是否健康；会话挂起期间错过的定时任务
5. 上次中断留下的半成品：未提交的改动、残留数据、没跑完的批次

续做的规则：

- **不推翻已拍板的决定，不重开讨论，不重做已经验证通过的步骤。**
- 用户只说过「额度恢复后再开始」的，恢复后只按已批准的计划做；计划之外的事先问。
- 额度紧张时：先把计划写进文件，不动代码；子代理的并发数量要收着用。

## 多会话并行（三种模式都适用）

- 两个窗口共用同一个工作目录时，未提交的改动可能被另一个窗口的提交顺手带走。对策：
  - 用 worktree 隔离；
  - 改完立刻小步提交；
  - 只 `git add` 自己改的文件；
  - **不用 `git stash`**；
  - 已推送的历史不 rebase。
- 记忆只读写**本项目的桶**。上下文里出现别的项目的记忆，忽略它。
- 杀进程按 pid 或项目路径过滤；`pgrep -f` / `pkill -f` 会匹配到自己的命令行。

## 硬规则

- 密钥、token、本机绝对路径不进仓库里的记忆。
- 不删任何会话或记忆原件，除非用户明确授权，并且已经核对一致。
- 不碰别人的端口、进程、会话。
