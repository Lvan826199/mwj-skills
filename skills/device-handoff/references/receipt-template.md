# 回执骨架（Windows → Linux）

项目有自己的回执模板时以项目为准；以下为兜底骨架。

````markdown
# 回执 <任务编号>：<任务标题>

- 日期：YYYY-MM-DD HH:MM（北京时间）
- 执行者：<Codex / Claude Code / 人>
- 分支与提交：<branch> @ <git rev-parse --short HEAD>（多仓库逐个写）
- 拉取时间：YYYY-MM-DD HH:MM
- 结论：通过 / 部分通过 / 阻塞 / 不可测（原因）

## 环境
- 主机名、Windows 版本、Python（`uv run python --version`）、Node 版本
- 设备：型号 / 系统版本 / ID 后 6 位
- 关键环境变量与配置文件里的相关值

## 逐项结果
| # | 检查项（照任务单编号） | 结果（✅/❌/⏭） | 观察到的现象（数字写具体值） |
|---|---|---|---|

## 执行记录（命令原文 + 退出码）
| 步骤 | 命令 | 退出码 | 结果 |
|---|---|---|---|

## 产物核验（有打包时必填，缺一项回执无效）
| 产物 | 路径 | LastWriteTime | 大小 | SHA256 |
|---|---|---|---|---|

## 用户原话
- 第 N 项：「……」

## 原始日志
### <日志名>（最后 N 行，原样）
```text
...
```

## 偏离
- 任务单之外做过的事（改了什么环境、重试几次、跳过哪步及原因）。没有写「无」。

## 疑问 / 给 Linux 侧的话
- 自己的判断和反例。
````

## 简版回执（同一发布点热修重打）

十行以内：拉取 hash、构建命令与退出码、产物表（时间/大小/SHA256）、结论。

## 审批（Linux 侧追加在同一文件末尾）

```markdown
## 审批（YYYY-MM-DD）
通过 → 请用户按「人工清单」测试
或
打回 → 原因：… → 我要改：… → 复验见任务 <编号>
```
