# 任务单 / 提示词骨架（Linux → Windows）

把 `<…>` 换成实际值。仓库协议模式写入 `当前任务.md`；粘贴模式整段放进一个 ```text 代码块给用户。

````text
# 任务 <编号>：<一句话标题>

## 目标与边界
- 本轮只做：<验证 #xx 修复 / 回答「xx 是否…」/ 打包 vX.Y.Z 并验收>
- 不做：不改任何代码；不打包（或：只打 exe，不打 APK）；不碰 <无关项目>
- 预计耗时：<约 N 分钟>

## 规矩
- 遵守仓库 <AGENTS.md / docs/打包发布.md §x / doc/联调/README.md>，不在这里复述。
- 只做命令行：git、构建、curl、读日志、写回执。不点界面、不截图、不抢焦点。
- 装包、重启应用、拔插数据线等会打断人的动作，先问一句，等人说「好了」再继续。
- 拿不准就停下，写进回执「疑问」，不要猜。

## 第 0 步：核对版本（不对就停）
cd <仓库目录>
git pull --ff-only
git log --oneline -1            # 必须是 <hash> 或更新
git status --short              # 必须为空（任务单列明的已知无关改动除外，写进回执「偏离」）
Get-Date -Format "yyyy-MM-dd HH:mm:ss"   # 记为拉取时间，回执里写上
<uv sync / npm install>

## 第 1 步：<标题>
- 命令：<原样可复制的命令>
- 收集：<要贴回的输出：最后 N 行 / 某一行 / 退出码 / 数值>
- 失败：<重试上限 N 次；仍失败标 ❌，贴完整栈和前后 20 行，继续下一步 / 停下>

## 第 2 步：……

## 人工清单（交给人，agent 只抄原话）
- [ ] <能照着点的一句话，例如：打开设置页，看下拉框文字是否看得清>

## 回执
- 写到：<doc/联调/回执/YYYY-MM-DD-任务<编号>.md / docs/回执/R<N>.md / 直接在对话里回复>
- 格式：照抄 <协议文件> 的骨架；日志原样贴、不截断；数字写具体值
- 产物（如有）：路径、LastWriteTime、大小、SHA256（LastWriteTime 必须晚于第 0 步的拉取时间）
- 提交：只 `git add <回执文件>`，commit message：<test(scope): 联调回执 <编号> / receipt: R<N> 可测>
- 完成后一句话回复：通过 / 部分通过 / 阻塞 + 回执文件名
````

## 复验提示词

在上面的骨架基础上：

- 标题写「任务 <编号>（复验 #<原编号>）」，目标写「验证 <hash> 对 <失败项> 的修复」。
- 第 0 步的 hash 换成修复提交。
- **只列未通过的项和本轮改动波及的项**；已通过且未受影响的项写一句「第 x、y 项上轮已通过，本轮不跑」。
- 上轮回执里的关键现象引用一句（带回执编号和日期），让执行侧知道要盯什么。
