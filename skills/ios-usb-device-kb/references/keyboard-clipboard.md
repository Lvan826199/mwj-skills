# 键盘与剪贴板

## 键盘

- **绝不调用 `create_keyboard_service`**：那条 createService 请求会让隧道 EOF（`IncompleteReadError 0/9`），在 18.3、26.2、27 上都会把连接冲断。（真机）
- 正确做法：把标准 39 字节键盘报告**直接发到设备自带的表面 512**。18.3 列出的 HID 表面有 257、512、1026、1280。（真机 18.3 / 26.2）
- 版本门槛：iOS 27 以下自动启用；27 上还没验证，要显式开启。（未决）
- **组合键要分成几份报文发**：
  1. 只按修饰键，保持 0.06s；
  2. 加上主键，保持 0.08s；
  3. 只剩修饰键，保持 0.06s；
  4. 全部抬起。

  如果修饰键和主键放在同一份位图里，会被当成普通的 v（分报文后的修复效果为真机 18.3 / 26.2；「iOS 先派发 V」这个机制是推断）。
- **中文输入**走「写剪贴板 + Cmd+V」。（真机 18.3 / 26.2，写剪贴板方向在 26.2 上也已验证）

## 剪贴板（pasteboardservice）

- 服务名是 `com.apple.coredevice.pasteboardservice`，只需要 RSD 隧道：不需要 HID，不受 9021 限制，写入时也不弹授权。（真机 18.3）
- **一条连接只受理一次 PULL**，第二次请求设备会直接关掉连接。每次请求都自己开连接、自己关；做诊断也要另开一条连接。（真机）

### 写入

- pmd3 11.3.1 不会自动分片。单帧超过 **16384 字节**，设备会发 GOAWAY（`too large frame size`），把整条连接掐断，所以要自己分片。（真机 18.3，10KB / 100KB 都测过）
- 设备从来不回 `SET_REPLY`：等 SET_REPLY 只给 **5s**，没等到就读回来核对，核对给 **8s**。

### 读取

- 分两步：先用 `allPromised` 只问有哪些格式，实测要 1～18 秒，波动很大，这一步预算 **20s**；纯文本再取数据，约 2.3～2.7s。富文本条目取数据只给 8s，最坏约 9s 就能出结论。
- 别的 App 复制的**富文本**，四种读取策略都超时，属于设备限制。绕行办法：先粘到一个纯文本框里，再复制一次。（真机 18.3）
- pmd3 里 `thresholdData` 的键名写错了，正确的是 `bytes`。
- 超时预算按实测最慢值留：读 **25s**。

## Python 异常的坑

- `IncompleteReadError` 是 `EOFError` 的子类。
- 从 Python 3.11 起，`TimeoutError` 是 `OSError` 的子类，**要先单独接住超时**，否则会被当成「连接被掐断」去重试。
- `asyncio.wait_for` 超时取消时，可能把底层异常吃掉。同一个功能如果走两条调用路径（CLI 和 sidecar），**两条都要真机验证**。
