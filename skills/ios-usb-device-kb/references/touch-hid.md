# 触控：CoreDevice HID

## 路线

- 链路：用户态隧道 → RSD → `com.apple.coredevice.universalhidservice`，向 `_ServiceID=257` 的触摸表面发 58 字节 HID 报告。不需要越狱，只要开着开发者模式。（真机 18.3）
- 鉴权：先尝试 `startmediastream`。新版 DDI 在 iOS 18.x 和 26.x 上返回 **9021**，这时直接连 HID（direct 模式）即可；iPadOS 27 上鉴权能通过（mediastream 模式）。**被拒再直连，不要按版本号猜。**（真机 18.3 / 26.2 / 27.0）
- 版本下限：触控要求 iOS 18 以上。17.7.4 上 HID 表面列表是空的，16 及以下没有 CoreDevice。视频不受这个限制。（真机）

## 单指报告

| 字段 | 值 |
|---|---|
| report id | `0x09` |
| 状态字节 | `0xC2` 按下 / `0x02` 抬起 |
| 坐标 | 16 位归一化（0..65535），**永远按物理竖屏坐标系** |
| 时间戳 | 48 位，从偏移 44 开始（单指布局） |

（真机 18.3）

## 多指：dtuhidd 整帧布局

- 一份报告装下全部触点：`byte1` = 当前触点数，`byte2` = 最大触点数（5，源码里是 `MAX_CONTACTS`）。
- 从偏移 3 开始，每个触点 5 字节：`[0xC0|slot（按下）或 slot（抬起）][x u16][y u16]`。
- **identity 表**按槽位索引：`byte[40 + slot] = slot + 1`。
- **时间戳从偏移 45 开始**（不是 44）。
- **每一帧都要带上全部活动触点**，漏掉的触点会被判为抬起。

（真机 18.3 / 26.2；27 未验）

### 历次失败与翻案（为什么只能用这种布局）

- 先后试过三种布局，都失败过，一度定论「双指缩放不可行」：
  - 多个触点塞进同一份报告；
  - 每根手指单独一份 `0xC2|slot` 报告；
  - idevice 的 packed 布局。
- 根因有两个：
  1. `0xC2` 占了 bit1，slot 0 和 2、slot 1 和 3 两两碰撞；
  2. packed 布局的 identity 表为 0，时间戳也早了一个字节。
- 有一次「packed 布局完全无反应」的结论后来作废了：测试工具没带坐标参数时，把像素间距当成了相对坐标，两根手指被钳在屏幕边缘不动。**判定「不可行」之前，先确认测试工具本身没问题。**

## 坐标与方向

- 换算用**逻辑点（pt）**，不要用像素除以 scale。例如 13 mini 是 375×812 pt。（真机）
- 报告永远按物理竖屏坐标，横屏要自己换算。
- 横屏游戏常常是「视频仍是竖向、内容侧着放」，只看物理姿态判断不出来，要查 SpringBoard 的界面方向（UIInterfaceOrientation 1–4）。（推断，待真机验证）

## 时序

- 「发完就退」的一次性客户端，断开前要**等约 150ms**：dtuhidd 提交一次触摸需要 15～65ms，提前断开，这次触摸会被取消。（真机 18.3）
- 鼠标拖动只保留最新位置（合并中间的点），否则触控事件会排队积压，松手后还在继续补画。（真机）
- 打开后台切换器用 **Home 双击**（Indigo page `0x0C`，usage `0x40`），用手势模拟不稳定。（真机 27）
