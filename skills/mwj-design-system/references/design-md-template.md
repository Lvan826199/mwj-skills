# 项目 DESIGN.md 模板

给**有自己风格的项目**用：把这个项目的视觉规则写成一份 `DESIGN.md`，以后写界面先读它，不用每次从代码里猜。

写法沿用 Google Stitch 提出的 `DESIGN.md`（文件头 YAML 放 token，正文写规则），章节按自己项目用得上的裁剪过。

## 写之前

- **放哪**：项目根 `DESIGN.md`；项目文档都在 `docs/` 或 `doc/` 下的，放那里也行。一个项目只放一份。
- **写现值，不写理想值**：token 的名字和值从代码里抄（CSS 变量文件、Tailwind 配置、主题文件），代码里是什么就写什么。想改风格是另一件事，先改代码再改这份文档。
- **token 名与代码一致**：代码里叫 `--paper`，这里就写 `paper`，不另起一套名字。
- **代码里直接写值、没有 token 的**（常见于字号、行高、组件高度）：照代码写值；代码里没有的键直接删，不填"未定义"。
- **重点写代码里看不出来的**：色值能 grep 到，「危险操作不用实底」「一屏只出现一次强调色」这种规则 grep 不到，这才是这份文档最值钱的部分。这类规则要问用户；问不到时，从代码反推的每一条后面标「推断，待确认」，不当定论写。
- **不确定的写进「已知缺口」**，不要编。
- **写入和修改都要用户同意**。

## 模板

把下面整段复制成项目的 `DESIGN.md`，按尖括号里的说明填，用不上的键和章节直接删。

````markdown
---
name: <项目名>
description: <一两句话：这个界面给人什么感觉，靠什么做到>
tokens-source: <token 在代码里的位置，例如 src/styles/tokens.css>

colors:
  <token 名>: "<色值>"
  # 底色、文字色、边线色、强调色、状态色，按代码里实际有的列

typography:
  <层级名，例如 title / body / caption>:
    fontFamily: <字体或字体 token>
    fontSize: <px>
    lineHeight: <px 或倍数>
    fontWeight: <字重>

rounded:
  <token 名>: <px>

spacing:
  <token 名>: <px>

components:
  <组件名，例如 button-primary>:
    backgroundColor: "{colors.<token 名>}"
    textColor: "{colors.<token 名>}"
    rounded: "{rounded.<token 名>}"
    # 属性按需增减（border、height、padding 等）
    # 颜色、圆角、间距一律用 {组.token 名} 引用上面的 token，不直接写色值
---

## 概览

<这个界面的气质和密度。写给没见过它的人：看完应该能想象出大概的样子。>

## 颜色

<每种颜色用在哪、不用在哪。尤其是强调色和状态色的使用边界。>

## 排版

<哪种字体给标题、哪种给正文；字重上限；有没有等宽字体的固定用途。>

## 布局

<页面骨架（导航在哪、内容区多宽）、栅格、常用间距节奏。>

## 层次

<靠什么分层：阴影、边线还是底色差。弹层和遮罩怎么处理。>

## 组件

<按钮、输入框、卡片、弹层、表格、导航等已定稿组件的规则，含 hover / 选中 / 禁用状态。只写已经落地的。>

## 该做 / 不该做

该做：

- <这个项目里一定要遵守的做法>

不该做：

- <这个项目里明确不要的做法，写上原因更好>

## 已知缺口

- <还没定稿的组件或场景。遇到这些先问，不要自己定。>
````

## 填完自查

- [ ] `colors` / `rounded` / `spacing` 里的每个 token 都能在 `tokens-source` 指向的文件里找到，名字和值一致
- [ ] `components` 里没有直接写死的色值
- [ ] 「该做 / 不该做」里代码看不出来的规则问过用户；没问到的都标了「推断，待确认」
- [ ] 没定稿的内容都在「已知缺口」里，没有混进正文

## 采用 MWJ 风格的项目

不需要照这个模板重写一遍 MWJ Token。要放 `DESIGN.md` 的话写清三件事就够：

```markdown
---
name: <项目名>
description: 采用 MWJ Design System，<标准 / 柔和>变体。
---

## 与 MWJ 规范的关系

- 变体：<标准 / 柔和>
- 完整规范：<MWJ_Design_System.md 在项目里的路径>
- 本项目特有的补充：<例如深色侧栏的 token 名和值；没有就写"无">
```
