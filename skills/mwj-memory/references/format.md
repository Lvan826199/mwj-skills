# 记忆格式规范与审计清单

## 单条记忆

文件名用 kebab-case，格式为 `<主题>-<要点>.md`。带状态的记忆，在文件名里加日期，例如 `handoff-2026-10-30.md`。

```markdown
---
name: <和文件名一致的 slug>
description: <一行，召回时靠它判断是否相关；不写版本号这类易变信息>
metadata:
  type: feedback        # user | feedback | project | reference
updated: 2026-10-30     # 可选；审计按它判断是否过期（克隆会刷新文件修改时间，不可靠）
---

<事实：一两句话。用户原话要照抄，并写上日期（YYYY-MM-DD，不写「昨天」「上周」）>

**Why:** <为什么要记住这一条：哪次出的事、用户为什么这么定>
**How to apply:** <下次遇到什么情况、具体怎么做>

相关：[[另一条记忆的 name]]
```

| type | 记什么 | 例子 |
|---|---|---|
| user | 用户是谁、擅长什么、偏好什么 | 「回复一律用中文」 |
| feedback | 用户的纠正，或者被用户认可的做法 | 「界面改动先自己截图看过再交」 |
| project | 进行中的工作、决定、约束（代码里看不出来的） | 「新项目以 AGENTS.md 为唯一规则源」 |
| reference | 外部资源的位置 | 「发版流程见 docs/打包发布.md §7」 |

## 索引 MEMORY.md

```markdown
# 记忆索引

- [标题](文件.md) — 一句话说明
```

- 一条记忆占一行；不写 frontmatter；摘要里不写版本号和状态（这些最容易过期）。
- 索引是每次会话都会加载的，要保持简短；细节放在各条记忆里。

## 放在哪里

| 内容 | 位置 |
|---|---|
| 跨机器、跨工具都要用的决定和踩坑 | 仓库 `docs/memory/`（或方案 B、C 对应的位置） |
| 只和这台机器有关的（路径、环境差异、本机服务） | 本机桶 |
| 凭据、口令 | 本机的私有配置文件（例如 `~/.config/<项目>/xxx.cred`），记忆里只写「凭据在哪」 |
| 和某一份具体内容绑定的（某本书、某台设备） | 跟着那份内容走的目录（加入 gitignore，或者放进私有仓库） |

## 审计清单（人工复核部分）

- [ ] 记忆里出现的版本号、状态，和当前的 tag、代码一致
  - 典型的过期情况：「最新发版 vX」「某功能尚未实现」「某某暂停」
- [ ] 「一律用某模型」「某项目别动」这类禁令或偏好，用户没有后来推翻
- [ ] 同名记忆在不同的桶里只有一个版本
  - 检查方法：`md5sum ~/.claude/projects/*/memory/<名字>.md`
- [ ] 上层目录的桶里没有本项目的记忆残留
- [ ] 没有凭据、内网 IP、私有绝对路径；公开仓库里也不能有书名、人名、内部系统名
- [ ] CLAUDE.md 或 AGENTS.md 里真的有 `@…MEMORY.md` 这一行
