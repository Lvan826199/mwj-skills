# UI Selfcheck：界面自检

用户原话：「这都改了多少遍了，你自己不是也可以浏览器启动截图看吗」「你现在确定你所有的页面修改的你都自己看过了吗？不允许有排版问题了」「你为什么没有自检出来？」

**没亲眼看过截图，不交付界面改动。** 人的时间只花在「好不好用」上，不花在「看不看得清、有没有错位」上。

## 第 1 步：识别技术栈，先找项目现成的工具

```bash
ls scripts/*shot* scripts/validate_*screenshot* scripts/lib/*screenshot* .tmp/selftest 2>/dev/null
grep -nE "截图|screenshot|视口|viewport|自检" AGENTS.md CLAUDE.md 2>/dev/null | head -20
```

- **项目有现成脚本或规定**（如 AiTestProject 的 `scripts/validate_ui_screenshots.cjs` + 固定 1920×1080、MoneyFree 的 `scripts/shot_pages.py` 桌面 1280 / 手机 390）→ **用项目的**，按项目规定的视口和文件命名。
- 没有 → 用本 skill 的 `scripts/shot.py`，用法见 `references/scenario-format.md`。

各技术栈怎么起服务、怎么喂数据，见 `references/stack-recipes.md`。

## 第 2 步：在隔离环境起服务

- **不碰真实数据，不碰用户正在用的服务。** 用临时数据目录或真实库的副本、单独的端口，或者用 `page.route` 模拟接口。
- 起服务前先查端口归属；本机还有别的项目和同事的服务在跑。
- 记下自己启动的进程 pid，第 6 步按 pid 停掉，禁止 `pkill` 进程名。

## 第 3 步：截图（覆盖面）

| 维度 | 要求 |
|---|---|
| 视口 | 项目有规定按项目；否则桌面 1920×1080（或 1280）+ 手机 390×844；有移动端的必须截手机 |
| 状态 | 至少：**有数据 / 空态或筛选无结果 / 弹窗或抽屉打开**；改到的地方涉及加载中、失败、禁用、超长文本、大数字的，也要截 |
| 页面 | 本轮改动的页面，加上共用组件改动波及的页面；新页面必须**从导航真实点进去**（见第 4 步） |
| 长页 | 不用 `full_page=True`，否则 ECharts 会画出界。改为把视口拉到页面全高（`--full-height`），看图时超长的按段看 |

截图统一放项目的 `.tmp/screenshots/<场景>/<时间戳>/`，文件名带上实际视口，例如 `home-1920x1080.png`。

## 第 4 步：机器检查

`shot.py` 会自动检查以下几项，任一不过就以退出码 1 结束：

- 控制台 error、pageerror
- 接口 4xx/5xx
- 横向溢出（`scrollWidth > clientWidth`）
- 白屏

另外人工补查：

- **导航可达**：新页面要从侧栏或菜单用真实点击进入，并断言地址变化、导航项高亮、面包屑正确。只能靠 URL 直达的不算完成（AiTestProject 要求路由、导航配置、侧栏分组、权限四处都注册）。
- **项目内的检查脚本**有就跑，例如 `scripts/check_nav_registration.cjs`。
- 有渲染测试的（MSCA 的 `*.render.test.js`）也跑一遍，它能抓到截图看不出来的模板错误和 prop 名写错。

## 第 5 步：亲自看图（每一张）

用 Read 逐张打开，对照 `references/visual-checklist.md` 检查。重点看：

- 文字有没有截断、重叠、溢出容器；数字有没有显示全（用户：「1.2w，12000,12999…必须显示全！」）
- 颜色和对比度：暗色背景上的灰字、下拉框白底白字
- 对齐、间距、垂直居中；手机端两侧有没有不该有的空隙、有没有撑满屏幕
- 缺失值有没有被渲染成 0；空态有没有提示文案
- 图表有没有画出来、坐标轴和图例是否完整

**发现问题 → 修 → 重截 → 再看**，直到挑不出毛病。

## 第 6 步：收尾与汇报

1. 按 pid 停掉自己起的临时服务，删除临时数据目录。截图保留，供人复查。
2. 用表格汇报，路径必须写绝对路径：

| 截图（绝对路径） | 验证了什么 | 结论 |
|---|---|---|
| `/…/home-1920x1080.png` | 首页有数据状态，卡片数字完整 | ✅ |

3. 写明**没覆盖到的部分**（例如「真机 WebView 未验」「暗色模式未截」）。
4. 「好不好用」这类只有人能判断的问题，列成一张短清单交给人；看得清、对得齐这类问题不要留给人。

## 硬规则

- 不看截图不交付；不要只截一张首页就说「都看过了」。
- 优先复用项目的脚本和规定，不临时另起一套。
- 不碰真实数据和用户在用的服务；不用 `pkill -f`（会匹配到自己的命令行，把自己的 shell 也杀掉）。
- 视口、文件名、状态覆盖按第 3 步执行。
- 优化建议（不是 bug 的）记进项目文档等用户拍板，不擅自改。

已知坑见 `references/known-pitfalls.md`，**起服务前先扫一眼**。
